## Scenario notes

- **cold-crl**: New validator per request; two CRL downloads over local HTTP. Requests by path: /intermediate.crl=15, /leaf.crl=15.
- **cold-ocsp**: New validator per request; OCSP-first with local HTTP. Requests by path: /intermediate-ocsp=15, /leaf-ocsp=15.
- **warm-cache**: Reused validator and cache; cached evidence revalidated, no network. Requests by path: none.
- **slow-source**: Cold CRL path with a 20 ms delay on the intermediate CRL. Requests by path: /intermediate.crl=10, /leaf.crl=10.
- **fast-revoked**: Leaf OCSP revoked while the intermediate response is delayed 100 ms. Requests by path: /intermediate-ocsp=10, /leaf-ocsp=10.
- **ocsp-to-crl**: OCSP endpoints return 503; both certificates fall back to CRLs. Requests by path: /intermediate-ocsp=10, /intermediate.crl=10, /leaf-ocsp=10, /leaf.crl=10.
- **crl-burst-40**: 40 concurrent requests share two in-flight CRL downloads. Requests by path: /intermediate.crl=1, /leaf.crl=1.
- **large-crl-inline-no-index**: Inline, raw DER cache only; 3000-entry CRL reparsed and scanned per request. Requests by path: none.
- **large-crl-inline-index**: Inline parsed CRL index cache; 3000-entry CRL parses once, then O(1) serial lookup. Requests by path: none.
- **large-crl-worker-no-index**: Worker pool, raw DER cache only; no parsed CRL index in workers. Requests by path: none.
- **large-crl-worker-index**: Worker pool with a bounded parsed CRL index cache inside each worker. Requests by path: none.
- **crl-validate-inline-no-index**: Isolated inline validateCrl: parse 3000-entry CRL and scan serials every call. Requests by path: none.
- **crl-validate-inline-index**: Isolated inline validateCrl with parsed CRL index cache; rechecks time and signature. Requests by path: none.
- **crl-validate-worker-no-index**: Isolated worker validateCrl without parsed CRL cache; one worker thread. Requests by path: none.
- **crl-validate-worker-index**: Isolated worker validateCrl with worker-local parsed CRL index cache. Requests by path: none.
- **cpu-path-5-cert**: Inline PKI path preparation for a five-certificate chain; no network. Requests by path: none.
- **cpu-path-5-cert-worker**: Same five-certificate path preparation dispatched through the worker pool. Requests by path: none.

## Interpretation

- Network scenarios are dominated by local HTTP round trips and evidence parsing; warm-cache scenarios isolate evidence revalidation without downloads.
- The four `crl-validate-*` scenarios isolate CRL validation itself: the 3000-entry CRL is parsed and scanned with no index, then reused through the parsed CRL index cache. The index cache still rechecks issuer, time, and signature on every call; it only avoids repeated ASN.1 parsing and linear serial scans.
- The four `large-crl-*` scenarios exercise the same comparison through the full validator and raw-DER cache; they include cache serialization, path setup, and profile overhead. Their totals are dominated by path validation, so use the isolated `crl-validate-*` rows to judge the index cache itself.
- `cpu-path-5-cert` isolates path-building CPU; the worker variants show the main-thread event-loop benefit of Piscina dispatch.
- Worker dispatch adds latency for small indexed CRL validations, but it keeps the main thread responsive when parsing or path work is the bottleneck. In this run, the parsed index removed most CRL parse/scan cost inline; the worker index cache was slower than inline index cache but had lower event-loop delay.
- The worker pool is optional and remains off unless the host creates and shares one. The measurement is a baseline, not a pass/fail gate; rerunning on the target deployment is required before changing defaults.
- Network concurrency, bounded queues, single-flight, and cancellation remain on the main thread; workers receive only DER/DTO. The pool is owned by the caller and must be closed.
